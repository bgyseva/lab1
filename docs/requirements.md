\# Требования к модулю "Сервис задач"



\## Описание модуля

Модуль "Сервис задач" предназначен для управления задачами студента. Модуль позволяет создавать задачи, изменять их статус, просматривать список и искать по ключевому слову. Данные сохраняются в JSON-файл.



\### Границы модуля

\*\*Модуль делает:\*\*

\- Хранение задач в памяти и JSON-файле

\- Операции: создание задачи, изменение статуса, получение списка, поиск по ключевому слову

\- Загрузка и сохранение данных в JSON



\*\*Модуль НЕ делает:\*\*

\- Не отвечает за пользовательский интерфейс

\- Не отвечает за сеть и передачу данных

\- Не отвечает за регистрацию и аутентификацию пользователей

\- Не управляет правами доступа



\---



\## Функциональные требования



\### R-01: Создание задачи

Модуль должен позволять создать задачу с \*\*названием\*\* и \*\*описанием\*\*.

\- \*\*Проверка\*\*: после создания задача появляется в списке и имеет уникальный идентификатор



\### R-02: Уникальный идентификатор

Модуль должен назначать каждой задаче уникальный идентификатор (ID).

\- \*\*Проверка\*\*: идентификатор существует, не пустой, не повторяется для разных задач



\### R-03: Статус при создании

Каждая задача должна иметь статус. Допустимые статусы: `"новая"`, `"в работе"`, `"завершена"`.

\- \*\*Проверка\*\*: при создании задачи статус устанавливается в `"новая"`



\### R-04: Изменение статуса

Модуль должен позволять изменять статус задачи на любой из допустимых.

\- \*\*Проверка\*\*: статус меняется только на допустимые значения и отображается в списке



\### R-05: Получение списка задач

Модуль должен возвращать список всех задач.

\- \*\*Проверка\*\*: список содержит все созданные задачи с полями ID, название, статус



\### R-06: Фильтрация по статусу

Модуль должен возвращать список задач с возможностью фильтрации по статусу.

\- \*\*Проверка\*\*: фильтр возвращает только задачи с указанным статусом



\### R-07: Поиск по ключевому слову

Модуль должен находить задачи, в названии или описании которых содержится заданное ключевое слово.

\- \*\*Проверка\*\*: поиск возвращает все задачи, содержащие ключевое слово в названии или описании



\### R-08: Поиск без учета регистра

Поиск по ключевому слову должен выполняться без учета регистра символов.

\- \*\*Проверка\*\*: поиск слова "ЗАДАЧА" находит задачу с названием "Важная задача"



\### R-09: Сохранение в JSON

Модуль должен автоматически сохранять все задачи в JSON-файл при каждом изменении.

\- \*\*Проверка\*\*: после создания или изменения задачи файл `tasks.json` обновляется и содержит актуальные данные



\### R-10: Загрузка из JSON

При запуске модуль должен загружать задачи из JSON-файла.

\- \*\*Проверка\*\*: после перезапуска модуля ранее созданные задачи доступны со всеми полями



\### R-11: Редактирование задачи

Модуль должен позволять изменять название и описание существующей задачи.

\- \*\*Проверка\*\*: после изменения поля содержат новые значения



\### R-12: Удаление задачи

Модуль должен позволять удалять задачу по идентификатору.

\- \*\*Проверка\*\*: после удаления задача отсутствует в списке



\---



\## Требования к данным и формату хранения



\### D-01: Расположение файла

Данные хранятся в файле `tasks.json` в той же директории, что и модуль.



\### D-02: Обязательные поля

Каждая задача должна содержать следующие поля:

\- `id` (число) — уникальный идентификатор

\- `title` (строка) — название задачи, не может быть пустым

\- `description` (строка) — описание задачи

\- `status` (строка) — статус задачи (`новая`, `в работе`, `завершена`)

\- `created\_at` (строка) — дата и время создания в формате ISO 8601



\### D-03: Структура JSON

Файл `tasks.json` должен содержать массив объектов задач.

\## Требования к ошибкам и исключениям



\### E-01: Пустое название

При попытке создать задачу с пустым названием модуль должен возвращать ошибку: `"Название задачи не может быть пустым"`

\- \*\*Проверка\*\*: задача не создается, возвращается сообщение об ошибке



\### E-02: Недопустимый статус

При попытке установить недопустимый статус модуль должен возвращать ошибку: `"Недопустимый статус. Допустимые: новая, в работе, завершена"`

\- \*\*Проверка\*\*: статус не меняется, возвращается сообщение об ошибке



\### E-03: Задача не найдена

При попытке изменить статус или удалить несуществующую задачу модуль должен возвращать ошибку: `"Задача с ID <id> не найдена"`

\- \*\*Проверка\*\*: операция не выполняется, возвращается сообщение об ошибке



\### E-04: Отсутствие файла

Если файл `tasks.json` отсутствует при запуске, модуль должен создать пустой массив задач и работать корректно.

\- \*\*Проверка\*\*: модуль запускается без ошибок, список задач пуст, при первой операции файл создается



\### E-05: Поврежденный файл

Если файл `tasks.json` поврежден (невалидный JSON), модуль должен:

1\. Создать резервную копию поврежденного файла

2\. Создать новый файл с пустым массивом

3\. Записать в лог сообщение об ошибке

\- \*\*Проверка\*\*: модуль запускается, создается файл `.bak` с поврежденными данными



\---



\## Критерии приемки



\### AC-01: Создание и сохранение

После создания задачи: задача появляется в списке, сохраняется в JSON, получает уникальный ID



\### AC-02: Персистентность

После перезапуска модуля: все задачи сохраняют поля, статусы и ID



\### AC-03: Поиск

Поиск находит задачи независимо от регистра, по части слова, возвращает пустой список при отсутствии результата



\### AC-04: Обработка ошибок

При попытке создать задачу без названия: задача не создается, возвращается понятная ошибка
